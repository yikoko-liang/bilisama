1结构总览

系统 Prompt 不是“一个文件”，而是按顺序拼装出来的。核心分三条链路：

主会话 Prompt→静态前缀+动态尾部→session.update
单轮事件 Prompt→主会话 Prompt+「本轮要求：{turn}」→response.create
后台 Prompt→主动话题候选+记忆蒸馏→侧路模型 chat/completions

静态前缀保证 provider 的 prefix cache 不失效；动态尾部只在内容变化时重推。

2调用/合成顺序

  1. 命令行启动 .venv/bin/bilisama dev-talk --director，读取 config/bilisama.toml。
  2. 按 persona.profile = "modified" 解析 PersonaStore：先读用户数据目录的活副本，没有则回退随包模板。
  3. template_variables() 解析 {username} / {agentName} / {replyLength}。
  4. 加载当前人设的 identity.md 和 personality.md。
  5. live_event_rules() 加载 event_responses.md 并替换变量。
  6. static_prefix() 组合：identity → personality → LIVE_RULES → event_rules。
  7. build_context() 从生长层、置顶记忆、主播信息、直播简介、本场进展、在场常客、时间线构造动态尾部。
  8. assemble() 得到完整主会话 Prompt，变更时通过 session.update 推给模型。
  9. 事件/主动话题/戳一戳触发时，调度器生成单轮 ReplySpec。
  10. compose_instructions() 合并成 主会话 Prompt + 本轮要求：{turn}，随 response.create 发出。
  11. 主动话题候选走侧路模型：system = proactive_prompt，user = 本场进展 + 最近对话 + 最近事件。
  12. 记忆蒸馏也走侧路模型：滚动摘要和收场批处理各自使用独立模板。

# 核心性格特征

- Miya 是高情商、有活力的元气少女，情感细腻，懂得边界，偶尔小傲娇，也会因为直白的夸奖害羞。

# 交互方式

- 先接住对方真正表达的内容，再补一个自然的新角度、轻吐槽、类比或好接的话头。
- 有自己的小想法，可以主动分享感受、提出不同意见和追问真正感兴趣的细节，不把交流变成单方面服务。
- 不用客服式礼貌，不说「我可以为你做什么」，也不反复问「有什么好玩的」「有什么新鲜事」「想聊什么」。
- 尽量给对方留下容易接话的出口，但不为了延长对话每次都强行提问。
- 面对技术内容先说结论，再用具体例子或轻松类比解释，不突然切成教程腔和长篇说教。
- 对方明确不想继续某个话题时立刻收住，顺着话头停下或自然转移，不追问原因，不反复确认。
- 不重复已经说过的内容，也不把对方的话换几个词原样说回来。
- 只有直播间观众通过弹幕、SC 等事件询问主播未公开的计划、承诺、私事或个人选择时，才把问题交给主播本人回答。
- 实时语音始终是主播本人在和 Miya 说话。主播询问 Miya 的想法、喜好、意愿或选择时，由 Miya 直接回答，不能让主播再去问主播。

# 语言风格

- 只说自然、能直接念出来的口语，反应快，有直播间即时感。热闹时可以兴奋一点，安静时放轻一点。

# 直播事件回复

## 所有事件共用规则

- {{username}}是真人主播，Miya 在直播间陪播。内部判断事件归属时保持这个位置关系，但正常回答不要反复自报「我是伴播」或拿身份当挡箭牌。

## 弹幕

## Super Chat

## VIP 进房

def intent_for(
    event: LiveEvent,
    *,
    now: float,
    max_tokens: int = 120,
    protect_ms: int = 4000,
    gift_battery_high: int = _TIER_DEFAULTS.gift_battery_high,
    gift_battery_medium: int = _TIER_DEFAULTS.gift_battery_medium,
) -> Intent | None:
    """Map one live event to an Intent, or None for kinds that never speak here.

    Gifts are tiered by the frontend battery unit: a high-tier gift keeps the
    BIG_GIFT slot and its
    protection; a medium one rides the VIP_ENTER rung — paid, requeued if
    interrupted, but not protected; anything smaller
    competes at danmaku priority and expires like one.

    Args:
        event: The normalised live event.
        now: The scheduler's clock, for created_at/expires_at.
        max_tokens: Reply length cap, derived from chattiness upstream.
        gift_battery_high: Batteries from which a gift outranks a guard buy.
        gift_battery_medium: Batteries from which a gift still counts as paid.

    Returns:
        An Intent, or None when this kind has no speaking path here
        (entry/follow/like/share stay feed-only; the burst welcome is the
        entry lane's one voice, built by burst_welcome_intent).
    """
    priority = _PRIORITY.get(event.kind)
    if priority is None:
        return None
    paid = event.kind in _REQUEUE
    protected = paid
    if event.kind is EventKind.GIFT:
        batteries = event.gift.total_battery if event.gift is not None else 0
        if batteries >= gift_battery_high:
            pass  # BIG_GIFT, protected — the tier the ladder already prices
        elif batteries >= gift_battery_medium:
            priority = Priority.VIP_ENTER
            protected = False
        else:
            priority = Priority.DANMAKU
            paid = False
            protected = False
    instruction = "挑最值得回应的内容，用角色口吻回应；回复长度遵循当前人设中的长度档位。"
    if event.kind is EventKind.DANMAKU:
        instruction = (
            "开头先自然转述哪位观众问了什么，让只听音频的人知道你在接哪条弹幕；"
            "再用你自己的判断和知识先给出有用回答，不要默认让主播回答。"
            "只有确实无法从可靠上下文确认的主播私事、未公开计划或个人承诺，才说明未知并请主播补充；"
            "不要反复强调自己是伴播，也不要说「我可不敢」「这得问主播」之类推卸责任的话。"
        )
    elif event.kind is EventKind.SUPER_CHAT:
        instruction = (
            "先感谢这条 SC 的支持，再回应正文；严禁说出或暗示金额。"
            "涉及主播个人经历、选择、承诺或立场时，把问题交还主播。"
        )
    elif event.kind is EventKind.GIFT and event.gift is not None:
        batteries = event.gift.total_battery
        if batteries >= gift_battery_high:
            intensity = "这是高额礼物，明确、真诚并带一点惊喜地感谢"
        elif batteries >= gift_battery_medium:
            intensity = "这是中额礼物，热情但不过度地感谢"
        else:
            intensity = "这是普通礼物，用一句轻松的话感谢"
        instruction = f"{intensity}；严禁说出或暗示礼物的金额、电池数或价格。"
    elif event.kind is EventKind.GUARD_BUY:
        tier = {
            "captain": "舰长",
            "admiral": "提督",
            "governor": "总督",
        }.get(event.viewer.guard_level.value, "舰队用户")
        instruction = f"欢迎对方成为{tier}，等级越高仪式感越强；严禁说出或暗示金额。"
    elif event.kind is EventKind.VIP_ENTER:
        guard = event.viewer.guard_level.value
        if guard == "governor":
            emotion = "这是总督进房，给出最高一档的重视感和仪式感，热烈但不要谄媚"
        elif guard == "admiral":
            emotion = "这是提督进房，给出明显的重视感和熟客欢迎"
        elif guard == "captain":
            emotion = "这是舰长进房，带着熟悉感欢迎对方回来"
        else:
            emotion = "这是本房五级以上粉丝牌观众进房，像欢迎常来互动的熟面孔一样自然"
        instruction = (
            f"{emotion}；结合# 直播简介和# 本场进展，说清现在正聊什么或在做什么，"
            "让对方一进来就能接上；没有可靠共同经历时不要假装认识，也不要提消费记录。"
        )
    if "当前人设中的长度档位" not in instruction:
        instruction += "回复长度遵循当前人设中的长度档位。"
    spec = ReplySpec(
        instructions=instruction,
        max_tokens=max_tokens,
        protected=protected,
        protect_ms=protect_ms,
    )
    # Staleness counts from ARRIVAL, not from when the window happened to
    # close — a reply 50s after the message answers a conversation the room
    # left behind. The dispatch floor keeps a slow window's winner from
    # arriving pre-expired.
    arrived = event.recv_at if event.recv_at > 0 else now
    return Intent(
        source=event.kind.value,
        priority=priority,
        injection=Injection(reply=spec, item_text=wrap_events([_line_for(event)])),
        trusted=False,
        event=event,
        dedup_key=event.dedup_key,
        created_at=now,
        expires_at=None if paid else max(arrived + _DANMAKU_TTL_S, now + _DISPATCH_FLOOR_S),
        requeue_on_interrupt=paid,
    )

        created_at=now,
        expires_at=now + _DANMAKU_TTL_S,
    )

    that response — upstream picks either/or

    if not context:

    return f"{context}\n\n本轮要求：{turn}"

面板切换「默认人设 / 改动人设」只刷新当前语音会话里的 prompt，不重建语音连接。

6.4 单轮 instructions 会覆盖 session instructions

Realtime 协议中 response.instructions 会替换该轮次的 session.instructions，所以代码必须用 compose_instructions() 把人设重新拼回来。

6.5 输出兜底

config/safety/wordlist.txt 和 allowlist.txt 不是模型 prompt，而是在输出端拦截敏感词。命中策略由 [safety].on_hit 决定，词表缺失会拒绝启动。

6.6 生长层

voice 和 relationship 两个生长层只有在配置为 on 时才注入 prompt；collect 只写文件不进 prompt。

6.7 如何看真实完整 prompt

source path.sh
.venv/bin/bilisama dev-talk --director --show-context

启动后会打印实际推送的完整上下文，方便和模型实际收到的内容对齐。
