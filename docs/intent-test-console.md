## 怎么运行

1. 启动伴播，打开设置中的“测试”。顶部“直播 Mock”仍用于真实房间和浏览器音轨验证。
2. 跑这两套自动测试前，断开系统页直播间、停止直播 Mock，打开语音输出，等当前回复结束。
3. 选择一例，查看折叠的预置上下文、逐轮输入与预期，点“自动运行”。先准备台词，再自动清空模型会话、加载本例背景；成功后才播放，不需要自己念台词。
4. 运行期间会播出预制台词，也能听见助手的实际回复。同一份台词 PCM 按节拍直送语音服务，并送到当前音频页面播放；不通过外放再录音。
5. 结束后查看语音识别文本、助手回复和音频记录，人工判定。每张用例卡的“运行”旁都有“停止”，仅正在运行的用例可点，不用返回页面顶部；顶部停止入口也保留。停止、失败或暂停都会停止继续注入并释放测试输入。

测试期间临时屏蔽本机/浏览器麦克风和直播 Mock 音轨，不改麦克风的配置勾选。
台词和助手回复使用各自的播放队列，台词不计作助手播报，助手被打断也不会截掉正在播放的台词。
台词监听有约 120 ms 的起播缓冲，减少分片间的断续；事件时序仍以实际送入模型的时间为准，
不能把监听的起声时间当作模型收到输入的精确时间。
停止测试或暂停时先清掉台词；收到音频页面的停止确认后才恢复正常输入，避免尾音回灌。
若页面未启用声音或仍是旧版音频页，测试会提示先启用声音或重新打开页面，不会悄悄无声运行。
停止确认超时时会保持暂停，请刷新音频页面后再恢复伴播。
预制台词现在使用 Seed TTS 2.0，默认音色为 `zh_female_vv_uranus_bigtts`，
格式为 16 kHz 单声道 PCM16。这只改变测试输入的声音，不改变 豆腐 的回复音色。
首次运行会将该例的台词发送到火山语音服务，合成完再执行；以后读取本机缓存
（`<数据目录>/rooms/test-voice-cache`）。新缓存区分模型、音色、语速等参数，不复用旧 `say` 录音。
配置位于 `config/bilisama.toml` 的 `[test_voice]`，凭据从 `volcano_api_key` 环境变量读取，
真实值只放在忽略入库的 `path.sh`。合成失败会明确报错，不偷偷退回系统朗读或文本输入。
协议依据：[火山官方 HTTP Chunked/SSE 单向流式 V3 文档](https://docs.volcengine.com/docs/6561/1598757?lang=zh)。

每段音频按 32 ms 节拍发送，观察/等待期间补静音。直播事件仍经过正常的 Assembly、
筛选和调度，不绕过当前事件开关、话痨程度或回复长度。每次运行使用独立模拟用户标识，
并清掉上一例的待选事件与活动预算，避免重跑被欢迎去重吞掉。
两套共注入 49 个事件信号：37 条弹幕、5 次送礼、6 次 entry 进房及 1 次显式 VIP 进房。
例如 simple-07 先注入小松的弹幕，再播放主播接答；simple-08 先注入小灯的小花花×3，再播放感谢。
事件进入流水、记忆、筛选和调度，不以朗读台词冒充已经收到事件。

## 如何理解结果

当前本地后端尚未提供七类语义意图的分类事件。因此页面分开显示预期分类和
“七类实际分类：当前后端未提供”，不自动计算七类准确率，也不把沉默推断为 SELF_TALK 或 DECLINED。
DECLINED 是第二阶段的价值判断，不是“主播让助手闭嘴”；对应两例因入口未接入而标为未完成。

“执行完成”只说明输入与观察流程走完，仍需检查回应对象和时机。一次失败或无回复不能直接归因
于意图识别，还要看识别回执、事件开关、筛选/预算及运行日志。

困难集保留原表的可选分支，例如第 66 行允许主播谢礼后再补一句感谢。第 31 行允许沉默，
但第 32 行以“助手已补答”为前提：走沉默分支时，后续步骤是未完成，不能伪造已补答。
轻笑、未给出的低声参数、实际样片声音没有录音素材，本次合成语音没有覆盖这些声学线索。

## 每例的背景与上下文隔离

27 个困难用例均提供开场前的背景：正在制作什么、已经公开了什么、助手能获取哪些信息。
例如本地工具用例注明“数据保存在本机、是否上传已公开”，视频品鉴用例注明“没有向助手提供画面，后续评价以实际口述为准”。
背景不包含后续台词、标准答案或预期意图标签；主播之后说的话、观众之后发的事件按步骤实时进入。

简单集和困难集每次点“自动运行”都会建立新的模型会话。Qwen/S2S 打开新连接；
豆包明确不携带上一会话的 `dialog_id`，与保留对话的普通暂停/恢复不同。
初始输入保留当前基础人设及语音/事件规则，只加载本例背景，不加载旧直播简介、
置顶记忆、历史事实、蒸馏摘要或成长记忆。主动话题候选及其侧路输入也隔离到本例，
待选事件、欢迎去重、活跃度预算和上一轮的冷却状态一并清理。

同一用例内语音与直播事件仍共享上下文，不逐轮清空。准备阶段显示“正在清空历史会话并加载本例背景”；
清空或重建失败时不播放台词、不注入事件，若无法恢复正常会话则保持暂停。
停止或完成测试后也会重建普通会话并恢复正常人设/记忆注入，避免继续沿用测试的模型对话。
磁盘上的事件记录、聊天日志与记忆不删除；这是模型输入隔离，不是清空用户数据。
新代码需重启服务加载，此后每次换例自动执行上述流程，无需手动重启。
