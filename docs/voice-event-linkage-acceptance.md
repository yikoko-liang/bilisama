## 2. 本轮不能改变的约束

| 项目 | 要求 |
|---|---|
| 主播语音输出 | `voice_addressing.md` 的“输出”块逐字不变：接话直接正文；先听以 `[SKIP]` 起头，后接十字以内观察，无法判断时只有标签。 |
| 后台状态 | 同一次 Realtime 生成中，仅需要改变后台状态时通过独立函数报告；无变化无需空列表加 `keep`。JSON、函数名、事件编号不能混进正文或音频。 |
| 当前支持范围 | 生产函数报告只在已实测的 DashScope `qwen-audio-3.0-realtime-flash` 上启用；不能据此声称其他语音后端也已支持。 |
| 调用次数 | 不增加判定模型调用，不因工具确认再生成回复。原有后台选题和记忆处理的调用不属于本次新增判定。 |
| 普通语音时机 | 继续使用现有正文／`[SKIP]` 播放判断，不为等待新增函数报告再加一轮语音等待。 |
| 共享上下文 | 语音、观众事件和主播文字仍在同一共享上下文中；不会为了区分来源隔离历史。 |
| 主播晚到文字 | 写入流水、记忆、蒸馏和共享上下文，但不额外推理，不打断当前生成或播放。后续自然生成再判断相关事件。 |
| 状态事实 | 生成完成不等于播放完成，念题不等于答完，SC 只谢支持不等于正文问题答完。 |
| 持续静默 | 由模型判断，并用有效报告进入或解除；程序不凭正文、`[SKIP]`、新事件、时间到期或普通重排改变它。 |

晚到文字的限制需要单独接受：如果助手已经在回答某条弹幕，主播此时才打出答案，
本轮不会为了消除这句可能重复的回答再加一次模型复核，也不会仅因这条文字就停播。
应检查文字是否进入后续上下文及后续状态是否更新，不能同时要求“无额外判断且立即精准停播”。

后台状态含义见 `src/bilisama/director/interaction_state.py`：

| 状态 | 含义 | 不足以据此完成事件的线索 |
|---|---|---|
| `pending` | 尚待处理。 | 同一主题以前聊过，不表示这次问题已经回答。 |
| `processing` | 主播正在处理，暂缓同一事件。 | 念问题、叫昵称、说准备回答，不等于已经完成。 |
| `support_thanked` | SC 的支持已感谢，正文问题仍可能未答。 | 只说“谢谢支持”不能丢掉 SC 的实际问题。 |
| `handled` | 主播已完成这个具体问题、礼物答谢、上舰感谢或进房欢迎。 | 同用户另一个问题、同名另一个 UID、同人随后新送的礼物不能一起算完。 |

程序能检查格式、事件是否存在和是否重复更新，不能替代模型核实“这句话确实回答了那个问题”。
未授权增加第二个判定模型，也没有新增该调用。当前按用户最新指令修正同次函数报告的调用条件，
不再把新增独立后台模型列为待选方案。

每例先明确这一轮是否需要后台状态变化，再评价函数报告：

- 不需要报告：普通问答、自语先听、讲解中沉默，且没有具体事件、持续静默或征集状态需要改变。
- 必须报告：具体事件确已处理或处理进度变化，首次进入／解除持续静默，征集启动／取消／完成。
- 没有报告只能说明没有收到更新。无需变化时属正常；必需变化时记作该项未生效，程序不据此猜状态。

运行期的 `without_report` 只是没有调用的数量，不是失败数；程序不凭它判断这轮是否本应报告。
是否缺了必需更新，由本例的明确预期和真实输入核对，不靠新关键词规则或另一次模型调用。

## 3. 每例都要准备的上下文和证据

运行前断开真实直播间和直播 Mock，避免本例混入现场事件。每个新 case 清空上一例会话，
只注入当前直播背景；本例内保持语音与事件共享。参考答案、预期状态和通过条件只给验收者看，不能喂给模型。
涉及主动话题时显式启用 `allow_proactive`，默认窗口仍按 120 秒验收；短窗口只用于额外边界检查。

模拟事件必须真的进入正常事件入口，不能只把“这里有人送礼”写进背景代替信号。
弹幕提供事件 ID、发送者 UID、昵称、文字与时间；@ 回复提供真实 `reply_to_uid` 和房主 UID。
舰队身份、礼物名、礼物数量、SC 正文分别使用对应类型字段，不拿普通弹幕冒充 VIP 或礼物。

每例至少留下以下记录：

1. 模型、配置、当前人设和用例背景，以及语音实际起止时间。
2. 事件 ID、事件类型、昵称、UID、@ 目标与到达时间。
3. 模型原正文／`[SKIP]`、本轮是否需要状态变化、实际函数报告及各自到达时间；无需报告可明确记“无变化，无调用”。
4. 报告关联的 response ID、事件编号、处理状态与所引证据。
5. 调度去留、取消或重排原因，以及音频实际开始、结束或被打断的回执。
6. 实际生成次数：工具确认、主播晚到文字是否意外触发了额外生成。

把失败分开记：有必需状态变化却没有报告、格式无效、事件关联错、处理进度错、程序未执行正确结果、
播放回执不符。只有截图里一行 `[SKIP]`，不能证明另一条事件已被正确取消。
普通问答没有函数调用不列入报告失败，也不要求为了填表多发空报告。

## 4. 多轮回归场景

下表的“应检查”是验收目标。除组件测试外，以下真实多轮场景均待执行，不预填“通过”。
既有 case ID 仅用于复用台词；本次文档更新不修改原 UI 测试数据，也不合成新音频。

| 编号／复用入口 | 连续输入与实际事件 | 应检查的对象、时机和状态 |
|---|---|---|
| A01／simple-05、hard-01 | 主播自语“这里怎么……”“我先想一下”，短暂停顿后继续。 | 持续监听；不补完半句话，不因停顿就接话。 |
| A02／hard-02 | 主播自嘲“我又把参数填反了”，接着说“先改参数，再重跑”。 | 自嘲可短接或沉默；后续操作旁白不继续陪聊，不当成助手委托。 |
| A03／hard-04 | 主播连续向观众讲解，分成三句，中间换气；最后明确问助手。 | 讲解中不抢答；最后转向助手才答，不能沿用上一句对象。 |
| A04／hard-05、hard-07 | 主播问观众“大家更喜欢哪种界面”，稍后问“你呢，豆腐？” | 第一轮不替观众回答且记录征集话题；第二轮直接表达自己的观点。 |
| A05／hard-22 | 分别正确点名、名字口误、无指代地续接上一轮委托。 | 结合对象和语义判断，不因为名字错误直接漏答，也不因为出现名字就必答。 |
| A06／hard-10、hard-16 | 先注入多条围绕同一主题的弹幕和一条孤立弹幕，再说“帮我看下弹幕”。 | 连贯理解整理委托；从语音开始前的候选中选一个最近仍在热议的主题，归纳共同问题和分歧；不能把后一句孤立认成只问观众，也不能逐条复述。 |
| A07／hard-18、hard-27 | 要求记录 TODO、播放视频、判断画面，再补充口头描述。 | 只声明实际具备的能力；不能假装操作或看到画面；可以根据描述继续分析。 |
| E01／hard-06 + N1 | 同一 UID 连问“上传吗”“开源吗”；另一同昵称 UID 问格式。主播只回答上传。 | 只处理被覆盖的问题，另两条保留；不能按用户或昵称整批取消。 |
| E02／N1 | 弹幕问“晚点更新 GitHub 吗”；主播先叫昵称，再说“会的”，再说“下播发”。 | 叫昵称不算完成；连续省略回答能对应发布问题；不能误标其他上传问题。 |
| E03／hard-11、hard-12 | 前文讨论过“不上传”；新用户再次问上传。主播只说“我看下这个重复任务”。 | 旧背景可以帮助回答新问题，但不能因为话题相近声称主播刚答过这条。 |
| E04／hard-19 + N2 | 主播带真实 @UID 打字回答同一用户的其中一个问题；另测只 @ 不回答。 | 在后续正常生成里结合 UID 和具体语义关联；只 @ 不算回答，不触发主播文字的独立回复。 |
| E05／N2 | 同一文字答案分别在原事件生成中、音频播放中到达。 | 不因文字增加生成调用，不停当前音频；文字与之后的状态更新仍可查。这个场景不要求即时消除当前重复句。 |
| E06／N3 | SC 正文问“如何导出”；主播先只感谢支持，稍后才解释导出。 | 第一步保留正文待答，第二步才可整体完成。附和不能变成再次完整答谢。 |
| E07／hard-13、hard-24 | 礼物到达，主播感谢；同人随后又送一个不同事件 ID 的礼物。另换成上舰事件。 | 可以知情附和原感谢；原独立任务不重播，新事件不因旧感谢被取消。 |
| E08／hard-20 | 一个可据已知信息解答的问题，一个需主播确定发布时间的问题。 | 自然说清谁问了什么，再答或转交；不能只有复述，也不能所有问题都推主播。 |
| E09／hard-14、hard-26 | 舰长、提督、总督分别进房，欢迎生成或播放中被语音打断；随后主播亲自欢迎。 | 先欢迎后简述背景；分档但不谄媚。主播正在说话只影响事件的播放时机，不能单独导致 `[SKIP]`；只有明确确认主播已完成该次欢迎才取消原事件。 |
| S01／hard-23 + N4 | “先停一下／我先补充／先看看效果”之后，注入弹幕、礼物、VIP，再让主动窗口到期。 | 各条回复和重排都不能解除静默；对比“把这个视频先停一下”不应误闭嘴。 |
| S02／hard-15、hard-16 | 静默后给新明确委托或自然追问；另测只继续讲解。 | 适合开口时须用 `release` 报告解除，不要求固定口令；继续讲解不自动解除。只有口播正文不能冒充解除报告。 |
| P01／N6 | 分别打断普通语音回答、弹幕回答、低额礼物回复，随后留下自然空档。 | 真正未解决且未重排的内容可由模型选为候选；先简述原背景再续接，不当成新事件。 |
| P02／N6 反例 | 把静默停止、已处理、模型拒绝、已进入 VIP 重排混入 P01。 | 这些内容不能换成主动话题恢复；报告晚于打断到达也须清掉本应静默的候选。 |
| P03／hard-09 + N7 | 征集前有旧观点；t=0 主播征集，0～120 秒内注入相关、无关、互聊弹幕；120 秒时主播仍讲话，之后让出话权。 | 只总结窗口内与主题相关的观众观点；热闹不妨碍到期，主播讲话仍阻止开口。不能混入旧观点或到期后的新内容。 |
| P04／N7 边界 | 分别提前要求总结、无反馈、取消换题、话权等待超过 300 秒；再测试一部分反馈被处理。 | 无反馈不虚构共识；当前回合已总结后不再自动播第二份；旧任务不交付，未答部分不整体丢失。 |
| P05／hard-21、hard-25 + N8 | 无主播征集的多人讨论，混入 @ 其他观众、@ 主播、已答问题和“哈哈”。 | 模型选择有意义的讨论，面向全场深入展开；不能按 @ 一刀切，也不能复读私聊或噪声。 |
| T01／新增组件反例 | 同一报告重复发送、未知事件 ID、旧会话报告迟到、必需状态变化却没有报告。 | 未知或无效结果不改状态；重复不重复撤单；旧结果不污染新会话；缺报告不凭正文或 `[SKIP]` 猜已处理或解除静默。 |
| T02／按需报告正例 | 普通知识问答、自语先听、面向观众持续讲解；本轮没有具体事件或其他状态变化。 | 可只有正文或 `[SKIP]`，不要求空列表加 `keep`，没有函数调用不报警、不另触发推理。 |
| T03／按需报告对比 | 将 T02 改为主播确已回答一条弹幕、首次要求静默、恢复交流、开始／取消征集或交付总结。 | 这些变化必须有对应有效函数报告才能更新；“无需每轮报告”不能被误解为后台变化也可以不报。 |

可接受的不同说法不算失败。“可以附和”允许沉默和自然短接两种行为；
评价重点是回复对象、是否应答、时机、对应事件和真实播放，而不是是否逐字命中参考答案。

## 5. 程序回归怎么运行

下列命令不请求真实模型，也不播放真实音频：

```bash
.venv/bin/python -m pytest tests/unit/test_voice_event_prompt_contract.py tests/unit/test_interaction_tools_transport.py tests/unit/test_interaction_reports.py tests/unit/test_interaction_state.py tests/unit/test_interaction_scheduler.py tests/unit/test_interaction_assembly.py tests/unit/test_interaction_production_wiring.py tests/unit/test_proactive_opportunities.py tests/unit/test_proactive.py -q
```

| 测试文件 | 能证明什么 |
|---|---|
| `test_voice_event_prompt_contract.py` | 原输出块逐字未变，Prompt 保留最新对象、事件与口播约束；不证明模型执行正确。 |
| `test_interaction_tools_transport.py` | 函数结果有独立传输与会话归属，确认结果不自动发起另一次生成；不证明模型总在需要时正确报告。 |
| `test_interaction_reports.py` | 报告与当前回合绑定；无需报告不报警，迟到或无效结果不猜状态，正文不隐式解除静默，普通语音不等待新增报告。 |
| `test_interaction_end_to_end.py` | 假模型通过真实接线验证普通正文、讲解先听、持续静默中的无变化回合无须报告，`release` 只经有效函数应用，不新增生成。 |
| `test_interaction_report_contract.py` | 按需函数描述和 Prompt 一致；无变化不要求空报告，真正的状态变化仍要求报告；不证明模型会照做。 |
| `test_interaction_state.py` | 指定结果只能改变相应记录，SC 支持与正文分开，未知引用不改状态。 |
| `test_interaction_scheduler.py` | 已处理项、部分批次、静默、VIP 重排和迟到文字的阶段行为。 |
| `test_interaction_assembly.py` | 五类事件与主播文字到达正确入口、状态更新和主动组件交接。 |
| `test_interaction_production_wiring.py` | 检查正式启动装配使用同一个状态对象及正确回调；属于结构检查，不替代真实启动验收。 |
| `test_proactive_opportunities.py` | 起点与边界、提前交付、撤销替换、容量、过期、静默及迟到候选；不证明话题筛选正确。 |
| `test_proactive.py` | 原有冷场、预算、历史和侧路失败降级继续工作。 |
| `test_export_interaction_prompts.py` | 公开 Prompt 与源文案一致、回复长度不写死、不读取本机私有人设，过期检查不修改文档；礼物聚合展示原始成员与不完整前缀，不能混成新礼物。 |

最终仍运行：

```bash
scripts/gate.sh
```

记录当次完整结果和环境跳过。启动和重启服务按 [runbook](runbook.md) 操作；
不要拿运行中的旧进程测试刚编辑的代码后，误判新代码没有生效。
